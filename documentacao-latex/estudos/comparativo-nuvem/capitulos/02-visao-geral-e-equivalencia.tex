\chapter{Visão geral e matriz de equivalência}
\label{cap:visao-geral}

Antes de mergulhar nas particularidades de cada um dos quatro eixos, este
capítulo apresenta o mapa completo de correspondência arquitetural entre a pilha
atual da Unooria no \textbf{GCP} e as suas arquiteturas equivalentes na
\textbf{AWS} e no \textbf{Azure}.

\begin{fichaeixo}{Síntese executiva da comparação entre as três nuvens}
\begin{campos}
  \item[GCP (Atual)] \nativo\enspace É a nuvem onde o desenho atual atinge a
    \textbf{menor fricção operacional por contrato}: um único Load Balancer
    global agrega tanto contêineres (\emph{Serverless NEGs} do Cloud Run) quanto
    buckets estáticos (\emph{Backend Buckets} do GCS) sob o mesmo IP e WAF; o
    Cloud Run combina alta concorrência (80 req/instância), CPU sempre alocada,
    WebSockets de 60 minutos e \emph{Jobs} de migração no mesmo modelo; o
    Pub/Sub faz \emph{push} HTTP autenticado por OIDC direto para a API; e o
    ecossistema Vertex AI concentra Gemini (64k saída, imagem \cd{4:5}, Live
    voz), Agent Engine (ADK nativo com sessões) e Vertex AI Search (busca
    estruturada + \emph{layout parser} com \cd{pageSpan} cobrado por uso).
  \item[AWS] \adaptacao\enspace Oferece maturidade exemplar em rede, banco de
    dados (RDS Multi-AZ + RDS Proxy) e entrega estática (CloudFront + S3 com
    OAC), mas \textbf{fragmenta peças que no GCP são unificadas}: o ALB não
    aponta para buckets S3 (exigindo CloudFront na frente de tudo para unificar
    borda e WAF); o AWS Lambda é incompatível com os requisitos da API (limite
    de 15 min e modelo de execução), levando ao \textbf{ECS Fargate} (ou App
    Runner com ressalvas de VPC/Jobs); o SQS não faz \emph{push} HTTP nativo
    sem peça intermediária (EventBridge Pipe / Lambda); e no eixo de IA, as
    \emph{Bedrock Knowledge Bases} exigem um banco vetorial subjacente (como
    OpenSearch Serverless, com piso fixo elevado em OCUs, ou Aurora pgvector) e
    reescrita do agente ADK.
  \item[Azure] \equivalente\enspace É a alternativa \textbf{mais próxima do
    modelo operacional do Cloud Run} para computação e borda: o \textbf{Azure
    Front Door} roteia nativamente para contêineres e Blob Storage com WAF
    integrado; o \textbf{Azure Container Apps} (ACA) entrega experiência muito
    similar ao Cloud Run (concorrência HTTP, \emph{scale-to-zero} ou réplicas
    mínimas, sessões WebSocket longas e \emph{Container Apps Jobs} para o
    \cd{prisma migrate deploy}); e o PostgreSQL Flexible Server já traz
    \emph{PgBouncer} embutido sem custo extra. No eixo de IA, combina Azure
    OpenAI (\cd{GPT-4o} + \cd{Realtime API}) e \textbf{Azure AI Search} com
    \emph{Document Intelligence}, mas ainda exige portar o código do agente ADK
    e gerenciar índices cobrados por hora.
\end{campos}
\end{fichaeixo}
